## 5. Actual Root Causes Identified

### Root Cause 1: Dotted Underline Striking Through Text (Bug 2)
1. **The Transparent Span Flaw**:
   ```tsx
   <div className="relative flex-1 min-w-0 flex items-end h-5 pb-0.5">
     <span className="font-mono font-bold text-slate-900 px-1 leading-[18px] z-10">
       {order.orderCode}
     </span>
     <div className="absolute inset-x-0 bottom-0 border-b border-dotted border-slate-700 pointer-events-none" />
   </div>
   ```
   `inset-x-0` forces the dotted line `<div>` to span the full width from `left: 0` to `right: 0`, passing directly underneath the text span. Because the text span has **no background color** (`bg-transparent`), the dotted line is physically drawn across the text area.
2. **`html2canvas` Font Ascent Miscalculation**:
   - `html2canvas` does not have access to native OS font tables. It estimates font baselines by creating an off-screen span with character 'M' and measuring offsetHeight.
   - For monospace and variable fonts on macOS (`GeistMono`, `ui-monospace`), `html2canvas` computes an inaccurate baseline.
   - In Chrome, this inaccuracy places the text glyph bottoms at `y=330–331`, touching the line.
   - In Safari (WebKit), the discrepancy is 6–8px larger, causing `ctx.fillText()` to be drawn directly across the middle of the dotted line, creating a strikethrough.

### Root Cause 2: "CASH MEMO" Pill Badge Clipping in WebKit (Bug 3)
1. **The CSS Transform Bug in `html2canvas`**:
   ```tsx
   <div className="relative flex items-center justify-center my-2.5 h-6">
     <div className="absolute inset-x-0 top-1/2 -translate-y-1/2 h-[2px] bg-slate-900 z-0" />
     <div className="relative z-10 bg-[#15803d] text-white text-xs font-black px-6 h-6 flex items-center justify-center rounded-full tracking-wider uppercase shadow-sm">
       CASH MEMO
     </div>
   </div>
   ```
2. In WebKit (Safari), `html2canvas` parses `-translate-y-1/2` (`transform: translateY(-50%)`) into a 2D matrix transformation.
3. When parsing sibling nodes inside a fixed-height container (`h-6` = 24px), `html2canvas` miscalculates the coordinate space origin.
4. It shifts the badge downward while constraining rendering to the container's 24px height. The bottom 8–10px of the badge—including the bottom curve of the pill and the bottom half of the letters **"CASH MEMO"**—falls outside the container bounds and is clipped off by `html2canvas`'s canvas clipping path.

### Root Cause 3: Downstream jsPDF Analysis (Section 1.6)
1. `PosInvoiceModal.tsx` lines 171–182:
   ```tsx
   const canvas = await captureInvoiceCanvas();
   const imgData = canvas.toDataURL("image/png");
   const pdf = new jsPDF({ orientation: "portrait", unit: "mm", format: "a4", compress: true });
   pdf.addImage(imgData, "PNG", 0, 0, 210, 297, undefined, "FAST");
   ```
2. **jsPDF is ruled OUT as a cause of distortion**:
   - The canvas generated by `captureInvoiceCanvas()` is `1588px × 2246px`, which perfectly matches the 210mm × 297mm A4 aspect ratio (`793.7px × 1122.5px` at scale 2).
   - `pdf.addImage` maps this image 1:1 onto the 210mm × 297mm page at (0,0).
   - The PNG download path and PDF download path share the exact same `captureInvoiceCanvas()` call. Every defect visible in the PDF is already present in the canvas before `jsPDF` is called.

## 6. Recommended Fix Direction (Description Only — No Code)

A future fix pass must address these structural root causes:

### 1. Dotted Underline Fields: Physical Separation Instead of Overlay
* **Stop running an absolute dotted line across the full width beneath the text.**
* Instead of an overlay where the line runs from `left: 0` behind transparent text, split each metadata field into a clean flex sequence:
  1. Field Label (`<span className="font-bold shrink-0">Sl. No. :</span>`)
  2. Field Value with an opaque background or dedicated width
  3. A dedicated dotted fill element (`<div className="flex-1 border-b border-dotted" />`) that **only begins AFTER the text ends** and fills the remaining rightward space.
* By ensuring the dotted line only exists in the empty space between the end of the text and the right boundary, it is physically impossible for the dotted line to ever strike through or collide with text glyphs, regardless of browser font-metric variances.

### 2. CASH MEMO Divider: Eliminate CSS Transforms
* **Remove `transform: translateY(-50%)` entirely.**
* Replace the overlapping absolute line with a standard 3-column flex or table row:
  - Left flank: `<div className="flex-1 border-t-2 border-slate-900" />`
  - Center: `<div className="shrink-0 bg-[#15803d] text-white rounded-full px-6 py-1">CASH MEMO</div>`
  - Right flank: `<div className="flex-1 border-t-2 border-slate-900" />`
* This eliminates negative margins, absolute positioning, and CSS transforms. The pill badge sits in normal document flow between two independent horizontal lines, guaranteeing zero clipping of rounded ends or text across all browser canvas engines.

### 3. Safari WebKit Whitespace & Image Preservation
* For text elements that squish together in WebKit exports (e.g. `Customer Signature`, disclaimers), replace single-space string concatenations with explicit non-breaking spaces (`&nbsp;`) or distinct block elements with margins.
* For the logo image, ensure image rendering uses an un-tainted `<img>` tag with explicit `crossOrigin="anonymous"` and natural dimensions pre-computed before canvas capture.
